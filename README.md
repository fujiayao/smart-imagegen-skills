# 智能生图skills · Smart ImageGen Skills

**一句话描述图片，自动整理提示词并选择可用生图通道。**

GitHub 仓库：[fujiayao/smart-imagegen-skills](https://github.com/fujiayao/smart-imagegen-skills)

项目简介：`一句话通用生图 Skill：YouMind 案例辅助提示词优化，ChatGPT 账号与中转 API 双模式自动路由。`

本项目是面向 Codex 的通用图片生成与编辑 Skill，不是新的生图模型，也不绑定抖音、社媒平台或营销场景。它把案例检索、提示词整理、登录/API 模式识别、网关模型发现和图片执行整合为一个入口。

> **日常使用不需要写 Skill 名、运行命令、选模板或选择后端。** 安装是一次性的；正常使用时只描述你想画什么，只有缺少必要的服务信息或凭据时才补充。

## 项目简述

### 想解决的问题

原本一次普通生图可能需要自己完善 prompt、确认账号或 API 模式、找服务配置、确认图片模型、选执行脚本、处理输出。Skill 应当吸收这些操作，而不是要求用户把它们再执行一遍。

本项目的设计目标是：**把操作复杂度留在内部，把自然语言入口留给用户。**

### 主要能力

- **自然语言入口**：生成图片、参考图编辑、重绘、风格转换；精确局部编辑保留其余内容。
- **默认提示词辅助**：尝试从 YouMind 公开案例中检索表达技法，由当前智能体整理成 prompt，不需要用户主动提“优化”。
- **账号模式**：识别 ChatGPT 账号登录后使用宿主内置 `image_gen`，不另索 API Key。
- **API 模式**：复用当前网关及匹配凭据、查询模型列表、选择兼容图片模型。
- **后台选择执行能力**：普通 API 单图/参考图编辑使用 AwakeFantasy 的受控客户端；高级参数在付费前选择官方 CLI 预检。
- **尽量不中断**：案例检索失败或无匹配时继续，不要求用户修复可选组件。
- **安全边界**：不提取 OAuth token 当 API Key，不静默换服务，不在结果不确定时自动换后端重复请求。
- **场景中立**：不默认竖版、科技风、Logo、水印、营销文案或任何社媒规则。

## 项目分析与架构

```text
用户一句自然语言 / 参考图
          │
          ▼
理解需求与保留项
          │
          ├─ 明确原词执行 / 精确局部编辑 ──────┐
          │                                 │
          ▼                                 │
YouMind：按需缓存公开 JSON + 本地关键词检索    │
          │                                 │
          ▼                                 │
当前智能体：参考案例技法、整理提示词 ◄────────┘
          │
          ▼
识别当前会话 / 本地配置中的通道
          │
          ├─ ChatGPT 账号 → 宿主内置 image_gen
          │
          └─ 中转 API → 当前网关 + 匹配 Key → 模型发现
                                  │
                                  ├─ 单图/普通编辑 → AwakeFantasy 客户端
                                  └─ 高级参数 → 官方 CLI（宿主需已提供）
                                              │
                                              ▼
                                      离线预检 → 正式执行 → 交付图片
```

### 三层分工

| 层 | 组件 | 负责什么 | 不负责什么 |
| --- | --- | --- | --- |
| 提示词层 | YouMind-OpenLab/gpt-image-2-prompts-search + 当前智能体 | 查找公开案例、提取构图/光线/材质表达、按本次需求改写 | YouMind 不是本项目调用的在线优化模型或生图 API |
| 路由层 | 本项目 `imagegen-relay` | 判断账号/API、绑定网关与 Key、发现图片模型、缺配置交互 | 不改全局登录或自动切换供应商 |
| 执行层 | 内置 image_gen / AwakeFantasy/relay-imagegen 客户端 / 官方 CLI | 真实生成/编辑、保存图片、检查输出 | 不替用户决定平台、风格或商业用途 |

`imagegen-relay` 是本项目内部 Skill 标识；`AwakeFantasy/relay-imagegen` 是第三方项目，两者不可混称。Skill 在界面中的显示名称为 **智能生图skills**。

### 关键取舍

1. **用规则做可靠路由，用智能体处理创作理解。** 脚本负责配置、模型发现和预检；最终提示词仍由当前智能体整理。
2. **案例是可选增强，不是强制模板选择。** 简单需求也默认尝试检索，但失败直接继续，避免为了“用上组件”阻断出图。
3. **不把“有 Key”误当“能生图”。** Key 必须对应已知服务；模型列表也不保证图片端点、额度、编辑权限或全部参数可用。
4. **后端自动选，不是失败自动换。** 事前选择支持参数的引擎；付费调用失败后不自动换后端，以免重复计费。
5. **不传播个人环境。** 使用通用输出目录和相对依赖路径，不携带个人账号、网关配置、缓存、图片或 Git 历史。

## 安装

### 环境要求

- Python **3.11+**（使用标准库 `tomllib`）。
- 支持加载本地 Skill 的 Codex 环境；账号模式还需要宿主提供内置图片工具及相应权限/额度。
- API 模式需要支持 GPT Image 兼容接口的服务。
- Windows、macOS、Linux 的基础代码采用通用路径；**新 Key 的 DPAPI 加密保存仅支持 Windows**。其它系统可临时隐藏输入，或通过安全环境配置供给。
- 官方高级 API 引擎是宿主外部依赖，不随本仓库分发；缺失时对应高级功能会明确报错。

### 一次性安装

克隆仓库并完成一次性安装：

```bash
git clone https://github.com/fujiayao/smart-imagegen-skills.git
cd smart-imagegen-skills
python -m pip install -r requirements.txt
python scripts/install.py
```

安装器默认将完整自包含 Skill 复制到用户目录下的 `.agents/skills/imagegen-relay/`，包括固定版本第三方客户端及授权声明。它**不覆盖或删除已有同名安装**，也不复制密钥、缓存或测试输出。若检测到旧版安装，请先备份并处理重复入口；不要同时保留多个相同标识的自动入口。

需要自定义位置时可用 `python scripts/install.py --target <目标父目录>/imagegen-relay`。目标必须不存在。不要把同名安装直接覆盖在私人版本上。

确认 Codex 已加载这个 Skill；如果当前界面尚未读取新技能，可重新打开后查看。安装器不会切换账号、改网关或索要 Key。已启用 `allow_implicit_invocation`，但宿主/模型的实际技能选择仍可能有偏差，不能保证所有环境 100% 自动命中。

> 依赖文件固定了当前验收使用的版本，目的是便于复现，不代表这些版本是最新版本或不存在安全问题。维护者应定期评估更新并重新测试。

## 使用方法

### 1. 直接生成

> 帮我画一只躺在窗边的橘猫，午后阳光，写实。

后台默认尝试 YouMind 案例检索并整理 prompt，再判断当前通道并生成。你不必提 YouMind，不必先选三套模板，也不必确认一个默认 prompt。

### 2. 使用参考图编辑

上传或提供图片后直接说：

> 把杯子的颜色改成深蓝色，其余内容和构图不要改变。

精确局部修改不引入风格案例；智能体整理编辑项与保留项后执行。

### 3. 重绘或风格转换

> 参考这张图，把场景改成雨后的夜晚，保留人物和主要构图。

这类创作默认仍尝试检索案例，但不能把案例中的品牌、人物、文案或画幅带入结果。

### 4. 原词执行，不改写

> 以下提示词原样执行，不要改写，也不要参考案例：……

此时跳过案例检索并保留原始 prompt，不因“优化”改掉用户明确内容。

### 5. 只要提示词，不生成

> 帮我把这个画面描述整理成生图提示词，先不要生成图片。

只交付 prompt，不触发收费图片调用。你要求先选模板或先审核时，才增加对应确认步骤。

### 6. 当前服务没有图片能力

智能体先判断是否确实缺模型/凭据，才请你补充：

- 沿用已知服务地址：只补缺少的 Key。
- 新图片服务：还需要 Base URL；单凭 Key 无法判断属于哪家服务。
- 在本地交互终端隐藏输入，由智能体启动后续发现/生成，不让你复制执行命令。
- 默认不保存；你明确希望下次自动复用时，Windows 下才 DPAPI 加密保存。

网络断开、401、403、429 或模型列表格式不兼容，不会统统归为“请给生图 Key”。

### 什么时候会参考 YouMind？

**普通生成/重绘默认尝试，包括简单需求。** 仅明确要求不改写/不参考案例，或精确局部编辑时跳过；检索不可用或无匹配时直接继续。YouMind 只提供公开案例，本项目不向其发送用户需求、参考图或 Key。检索为本地关键词匹配，不是语义向量检索；无法保证每次都能命中合适案例。

## 配置与凭据

这些是维护/自动化选项，**不是日常用户必须手工配置的步骤**。

| 变量或参数 | 用途 |
| --- | --- |
| `CODEX_HOME` | Codex 配置和官方引擎查找根目录；默认用户目录下 `.codex` |
| `IMAGEGEN_RELAY_CONFIG` | 显式独立配置文件；内容视为敏感，不提交 Git |
| `IMAGEGEN_API_KEY` + `IMAGEGEN_BASE_URL` | 成对的专用生图服务凭据；不自动加载 `.env` 文件 |
| `IMAGEGEN_MODEL` | 可选图片模型；不把聊天模型当图片模型 |
| `IMAGEGEN_OUTPUT_DIR` | 默认图片输出目录；未设置时是执行命令所在目录的 `outputs/images/` |
| `--mode native / relay` | 当前会话证据与磁盘默认不同或需要排查时显式固定 |
| `--backend auto` | 默认事前自动选择后端，不改变网关或凭据 |

网关配置优先级和错误分类见 [routing.md](skills/imagegen-relay/references/routing.md)。只读复用当前匹配配置，不把其它站点的 Key 发送给当前网关；不自动切换 cc-switch 当前供应商。

### 输出与本地隐私

- API 默认输出：当前工作目录的 `outputs/images/`；可明确指定其它位置。
- AwakeFantasy 分支还会生成 `.meta.json`，含 prompt、参考图路径和真实图片尺寸；虽然不含 Key，仍属于可能敏感的创作数据。
- 不覆盖现有图片，除非用户明确授权覆盖。
- `.gitignore` 忽略输出、元数据、缓存、日志、凭据和常见用户配置。若把输出写到其它不受规则覆盖的位置，仍需自己保护。
- 内置生图的宿主缓存不由本项目控制，不能保证所有模式都采用相同本地目录或元数据格式。

发布前建议执行：

```bash
python scripts/check_release.py
git status --short
git add .
git diff --cached
```

确认暂存区只有项目源码、文档与允许分发的第三方文件，再提交并推送到自己的仓库。**扫描器是启发式检查，不保证绝对匿名；.gitignore 也不会删除已经进入历史的敏感文件。** 如 Key 曾泄漏，请先撤销/轮换，不要只补一条忽略规则。

仓库发布名称建议保持 `smart-imagegen-skills`。本地工具不会替你创建 GitHub 仓库、提交代码、设置公开权限或推送；公开发布应在你检查内容并确认后进行。

## 限制与路线

### 当前限制

- API 执行主要适配 `gpt-image-*` 兼容协议，不承诺任意厂商的图片 Key 都能直接使用。
- 当前代码有模型偏好顺序，但不是“自动判断最新/最强”；新模型需补充验证。
- 账号工具和官方高级引擎是否可用，取决于宿主安装、账号权限及服务配置。
- YouMind 为固定版本、局部缓存与关键词检索；不保证每次都能匹配，也不自动下载全库。
- Windows 之外未实现本地加密持久化；不把“不保存”改成明文落盘。
- 真实服务可能不接受 `auto` 尺寸/质量；遇到不兼容应说明并调整，不暗中换服务。
- API 请求和结果 URL 下载由不同层处理，详见组件说明；不要将“凭据请求禁止重定向”理解为所有第三方下载都没有重定向。
- 本项目遵守宿主和服务的内容、安全、权限、计费及授权限制，不提供绕过能力。

### 可选演进方向

- 增加其它图片协议的独立适配器，不混淆供应商能力。
- 改善本地案例检索与分类选择，同时保持数据来源、权限和本地隐私边界。
- 在用户明确授权和预算约束下增加真实供应商兼容性验证。
- 为其它系统实现可靠的系统凭据存储，而不是增加明文配置。

这些是后续方向，不是当前已实现能力。
